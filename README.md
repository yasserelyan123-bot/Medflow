# ClinicFlow — نسخة Supabase (بدون Backend تنشره بنفسك)

في النسخة دي، مفيش سيرفر Python تنشره على Render أو أي استضافة تانية.
الفرونت إند بيكلّم Supabase مباشرة، وSupabase هو اللي بيحفظ البيانات
ويطبّق قواعد الأمان (عزل بيانات كل عيادة عن التانية).

## الملفات

```
clinicflow_supabase/
├── schema.sql          ← الصقه في Supabase SQL Editor مرة واحدة
├── frontend/
│   ├── index.html      ← فيه مكان تحط فيه رابط ومفتاح مشروعك
│   └── app.js
└── README.md
```

## الخطوات بالترتيب (كلها بالماوس/باللمس، بدون Terminal)

### 1) أنشئ مشروع Supabase جديد
من لوحة تحكم Supabase بتاعتك: **New Project** → اختار اسم وباسورد لقاعدة البيانات
→ استنى دقيقة لحد ما يخلص الإنشاء.

### 2) شغّل ملف الـ SQL
من قائمة المشروع على اليسار: **SQL Editor** → **New query**
افتح ملف `schema.sql` (من نفس المجلد اللي بعتّهولك)، انسخ **كل محتواه**، الصقه في المحرر،
ودوس **Run**. لازم يظهر "Success. No rows returned" في الآخر.

### 3) عطّل تأكيد البريد الإلكتروني (لتسهيل التجربة الأولى)
**Authentication** → **Providers** → **Email** → دوّر على خيار
**"Confirm email"** وشيّله (Off). لو سايبه شغّال، هتحتاج تفتح بريدك
الإلكتروني وتأكّد الحساب بعد كل تسجيل قبل ما تقدر تسجّل دخول.

### 4) هات بيانات الاتصال بمشروعك
**Settings** → **API** → هتلاقي:
- **Project URL** (شكله: `https://xxxxx.supabase.co`)
- **anon public** key (سطر طويل يبدأ بـ `eyJ...`)

### 5) عدّل ملف `frontend/index.html`
افتحه وغيّر السطرين دول بالقيم اللي نسختها فوق:
```js
window.SUPABASE_URL = 'https://xxxxx.supabase.co';
window.SUPABASE_ANON_KEY = 'eyJ...';
```
احفظ الملف.

### 6) ارفع مجلد `frontend/` بس على GitHub
نفس الطريقة اللي عملتها قبل كده: **Add file** → **Upload files** →
ارفع `index.html` و `app.js` (ملفين بس).

### 7) فعّل GitHub Pages (لو لسه مش مفعّل)
**Settings** → **Pages** → اختار الفرع والمجلد → **Save**.

### 8) جرّب
افتح رابط الموقع → "عيادة جديدة؟ أنشئ حسابًا" → املا البيانات
(هتحتاج بريد إلكتروني حقيقي وباسورد 6 أحرف على الأقل) → **إنشاء العيادة**.

لو ظهرت رسالة خطأ، ابعتلي **نص الرسالة بالظبط** أو screenshot، وهنحلها.

## ملاحظة أمان

الـ **anon public key** مصمم أصلاً إنه يكون ظاهر في كود الفرونت إند —
مش سرّي زي الباسورد. الحماية الحقيقية بتحصل من قواعد **Row Level Security**
اللي في `schema.sql`، مش من إخفاء المفتاح ده.
